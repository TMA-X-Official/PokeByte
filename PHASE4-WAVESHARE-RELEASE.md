# PokéByte — Phase 4 Waveshare Release

**Status: In progress — preparation and hardware-port work; NOT READY TO FLASH.**

**User decision (24 October 2026):** Phases 1–3 completed and approved on Windows. The user rejected both experimental gameplay prototypes (Forest Trail and Pokémon-style battles) and asked to remove Gameplay Expansion. **The Waveshare release was renumbered Phase 4**. Do not ship either Adventure or Battle. Review PRs [#17](https://github.com/TMA-X-Official/PokeByte/pull/17) and [#18](https://github.com/TMA-X-Official/PokeByte/pull/18) were both closed *without merging*, with code history retained for traceability. The active roadmap now consists of **Phases 1–4**.

**Current engineering branch:** [`pokebyte-phase4-waveshare-release-prep`](https://github.com/TMA-X-Official/PokeByte/tree/pokebyte-phase4-waveshare-release-prep), created directly from the user-approved Phase 3 source (not from rejected gameplay prototypes). Detailed engineering gates and safety notes: [Phase 4 release preparation on that branch](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/pokebyte/PHASE4-WAVESHARE-RELEASE.md).

**Review and first checks:** [former Phase 5 draft PR #19 (superseded by the renumbered review)](https://github.com/TMA-X-Official/PokeByte/pull/19), and [passed ESP32-S3 compile, host logic, lint, generated-file and translations CI #40132890760](https://github.com/TMA-X-Official/PokeByte/actions/runs/40132890760). This was a **preflight compile of the original hardware code**, not proof that accepted PC-only features run on Waveshare.

**Verified art-only SD staging (separate private archive):** `PokeByte-Phase5-Verified-MicroSD-Assets-STAGING.zip` (SHA-256 `d70a674139e0e5a7a7acce4a508f7b8b2c1e9a33250c04d19ef3d9078e861442`), sourced directly from the exact approved Phase 3 ZIP. Contains 12 approved BMPs and 303 `.bin` assets, including `thumbs.bin`. **Not firmware, not yet a usable upgrade, and should not be copied onto the current card before backup/embedded path verification.**

**Trusted source/asset reference:** [`pokebyte-phase3-pack03-distinct-moments`](https://github.com/TMA-X-Official/PokeByte/tree/pokebyte-phase3-pack03-distinct-moments), accepted ZIP `PokeByte-Phase3-Pack03-Distinct-Surprises-Approved-Art-Windows.zip` (SHA-256 `2b2e185737e182c84dbbd39594f823fa36ac74d589b4d4b5a826e674f37e61c0`), and [the 12 approved BMP / original PMD checksum manifest](APPROVED-ASSETS.md).

**Immediate tasks:** verify target is specifically Waveshare **ESP32-S3-Touch-AMOLED-1.75** (not 1.75C); compile an ESP32-S3 hardware build without flashing; prepare verified microSD assets; port and test **all** accepted Windows-only scenes, ambience and personality features to embedded hardware; audit flash/NVS/partition safety, physical touch/PMU/RTC/audio/SD, and firmware rollback before any flash instructions.

**Safety boundary:** The existing `main` firmware (TamaPoke v1.17) and user save remain untouched. Never format a user microSD or flash/erase a connected board automatically. The Phase 4 branch explicitly disables auto-formatting microSD on mount failure as its first safeguard. No hardware image should be called "PokéByte Phases 1–3" merely because the Arduino compiler succeeds: current Phase 1–3 enhancements have important `POKEBYTE_PC`-only implementations that must be ported.

**Dedicated installer website in development:** The user requested a PokéByte-branded equivalent to the original TamaPoke browser installer. A responsive [PokéByte installation-page preview](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/web/pokebyte/index.html) is on the Phase 4 development branch, with [setup/readiness notes](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/web/pokebyte/README.md). It shows the correct Waveshare model, backups, firmware/asset steps and approved Phases 1–3. **The flash button is disabled; there is no active firmware manifest, executable firmware or Web Serial transfer.** The existing `web/index.html` still installs *original TamaPoke*, not PokéByte, and was left untouched. [Installer preview safety CI passed](https://github.com/TMA-X-Official/PokeByte/actions/runs/40134413049). The new page is **not hosted as a live installer** and must remain locked until the actual firmware port, backup/rollback and hardware tests are complete and approved.

**Before connecting your Waveshare:** Follow the new [Phase 4 Windows first-connection and read-only backup guide](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/pokebyte/PHASE4-FIRST-CONNECTION-WINDOWS.md). A safe `tools/phase4_waveshare_backup.py` tool first prints the plan and performs full flash read only with explicit `--execute`; it never flashes or erases. Preserve the current 16 MB device flash/NVS and copy the entire microSD card privately. The physical firmware is still **not** ready for installation.

**Branding:** The user's actual PokéByte logo has been included on the GitHub README and on the locked installer preview as an optimized thumbnail. The high-resolution original upload remains available in the user's project files. [Phase 4 review PR #20](https://github.com/TMA-X-Official/PokeByte/pull/20) supersedes old Phase 5 PR #19, which was closed unmerged.
