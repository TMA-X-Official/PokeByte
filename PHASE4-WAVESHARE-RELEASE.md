# PokéByte — Phase 4 Waveshare Release

**Status: First native ESP32-S3 port now implemented and successfully compiled; physical device and USB installer NOT yet validated, NOT READY TO FLASH.**

**User decision (24 October 2026):** Phases 1–3 completed and approved on Windows. The user rejected both experimental gameplay prototypes (Forest Trail and Pokémon-style battles) and asked to remove Gameplay Expansion. **The Waveshare release was renumbered Phase 4**. Do not ship either Adventure or Battle. Review PRs [#17](https://github.com/TMA-X-Official/PokeByte/pull/17) and [#18](https://github.com/TMA-X-Official/PokeByte/pull/18) were both closed *without merging*, with code history retained for traceability. The active roadmap now consists of **Phases 1–4**.

**Implementation milestone:** The Phase 4 branch now has [a native hardware-port status report](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/pokebyte/PHASE4-NATIVE-PORT-STATUS.md). It compiles accepted Windows Phases 1–3 for native Arduino: exact approved 466×466 SD BMP backgrounds cached in PSRAM, limited grass/pollen/fireflies, optional rain/snow, native temperament/Bond/one-shot surprise behavior, weather touch controls and CRC rejection of bad art. **An ESP32-S3 build and game-logic tests have passed, but no physical board has been tested yet.** Still required: USB flash/NVS recovery, Web Serial browser client and asset sync QA, correct device verification, physical display/touch/PMU/RTC/audio/frame timing, and preserved saved-Pokémon reboot tests.

**No microSD adapter required for the next read-only check:** The user currently has a working microSD containing Pokémon sprites but no PC card reader. The approved Phase 3 private ZIP already backs up the **303 known original sprite/thumbnail binaries**. This is **not proof** that the physical card contains no additional files. The original TamaPoke USB serial interface supports `LS`, `SDINFO` and upload-only `PUT`, **not SD file download/readback**; no complete SD copy is possible over the existing USB protocol. **Leave the card inserted and untouched**, do not format or copy any new files, and use the [first-connection Windows instructions](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/pokebyte/PHASE4-FIRST-CONNECTION-WINDOWS.md) for a separate, read-only **internal 16 MB flash/NVS backup** over USB. A future SD write still needs a physical card backup or an explicitly reviewed separate restore plan.

**Safety boundary:** The existing `main` firmware (TamaPoke v1.17) and user save remain untouched. Never format a user microSD or flash/erase a connected board automatically. The Phase 4 branch explicitly disables auto-formatting microSD on mount failure as its first safeguard. The native Phase 1–3 code is now implemented in the hardware branch, but **a compiler success is not proof the hardware works safely**. Do not expose the installer before actual user-device tests and verified backups.

**One-click installation is the user-required release experience (25 October 2026):** A visitor must only open the hosted PokéByte page, connect the supported Waveshare to USB-C, click **Install PokéByte**, and approve browser USB/safety prompts. The **website automatically fetches verified firmware and checks/uploads original sprites plus approved scenes over Web Serial**. No manual firmware/ZIP download, Python, Arduino IDE, CLI or microSD reader is allowed as an *ordinary installation step*. Existing owners need an in-browser, verified firmware/save backup and no forced erase; any private backup file should be retained by the owner. The original TamaPoke serial `PUT` protocol supports only sprite uploads under `/mons`, not scene delivery or full-card backups: the native firmware now includes an initial **CRC-gated, non-overwriting `PBCAPS`/`PBCRC`/`PBPUT` asset protocol** for known original sprites and 12 BMP scenes. This is firmware groundwork only: a matching browser client, interruption and physical tests, plus a full SD-card recovery strategy are **still missing**; do not claim completed one-click setup. Browser ESP Web Tools supports automatic manifest-based flashing, but can erase all on a new install by default, so safe update checks are mandatory. [Implementation acceptance contract](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/web/pokebyte/ONE-CLICK-INSTALLER-REQUIREMENTS.md). **Current install button remains locked** until a real, tested, user-approved PokéByte firmware exists.

**Dedicated installer website in development:** The user requested a PokéByte-branded equivalent to the original TamaPoke browser installer. A responsive [PokéByte installation-page preview](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/web/pokebyte/index.html) is on the Phase 4 development branch, with [setup/readiness notes](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/web/pokebyte/README.md). It shows the correct Waveshare model, backups, firmware/asset steps and approved Phases 1–3. **The flash button is disabled; there is no active firmware manifest, executable firmware or Web Serial transfer.** The existing `web/index.html` still installs *original TamaPoke*, not PokéByte, and was left untouched. [Installer preview safety CI passed](https://github.com/TMA-X-Official/PokeByte/actions/runs/40134413049). The new page is **not hosted as a live installer** and must remain locked until the actual firmware port, backup/rollback and hardware tests are complete and approved.

**Before connecting your Waveshare:** Follow the new [Phase 4 Windows first-connection and read-only backup guide](https://github.com/TMA-X-Official/PokeByte/blob/pokebyte-phase4-waveshare-release-prep/pokebyte/PHASE4-FIRST-CONNECTION-WINDOWS.md). A safe `tools/phase4_waveshare_backup.py` tool first prints the plan and performs full flash read only with explicit `--execute`; it never flashes or erases. Preserve the current 16 MB device flash/NVS and copy the entire microSD card privately. The physical firmware is still **not** ready for installation.
